# سيناريو مناقشة وتشغيل نطاق Nitaq

## العرض المختصر — 6 إلى 8 دقائق

### 1. المشكلة — 45 ثانية

«بيانات اللوجستيات الإقليمية في السعودية متاحة علنًا، لكنها موزعة بين جداول
ومصادر وتعريفات مختلفة. كما أن مقارنة الأرقام الخام تحابي المناطق الأكبر. لذلك
بنينا نطاق Nitaq لتجميع الأدلة، توثيق حدودها، وإتاحة مقارنات قابلة للدفاع عنها.»

### 2. قرار المنتج — 45 ثانية

«نطاق Nitaq ليس Dashboard ثابتًا ولا بنك إجابات محفوظة. هو Copilot حواري
يفهم السؤال، ويستكشف الأدلة، ويقدم ترشيحًا أوليًا وفق البيانات والمعايير المتاحة.
لا توجد منطقة فائزة محفوظة، والنتيجة تتغير إذا تغير السؤال أو المؤشر أو الأوزان.»

### 3. المعمارية — 60 ثانية

«Complexity Router يختار أصغر مسار كافٍ للسؤال. أدوات Python تنفذ جميع الحسابات،
وRAG يجلب التعريف والمنهجية والقيود مع الصفحة. إذا كان السؤال حديثًا أو لم يجد RAG
دليلًا كافيًا، ينتقل Research Agent إلى المواقع الرسمية المسموحة مع الرابط وتاريخ الوصول.
Guardrails تراجع الأرقام والفائز والترتيب قبل عرض الجواب.
الرسوم تختارها أدوات عرض محدودة ومختبرة؛ النموذج لا يكتب كود الرسم.»

### 4. تجربة حية — 3 دقائق

1. ابدأ بسؤال: **«قارن بين الرياض ومكة في طلبات التوصيل والمستودعات لعام 2024»**.
2. وضح أن لوحة الأدلة تظهر أسفل الإجابة عند الحاجة، وتتضمن القيم الخام والمطبعة والرسوم والمصادر.
3. افتح تبويب **الأدلة** وأظهر `compare_regions` والمصدر والقيود.
4. اسأل: **«ما تعريف مساحة المستودعات وما حدود استخدامها؟»** لعرض RAG والاستشهاد.
5. اسأل: **«هل عندنا بيانات الإيجارات والإشغال والربحية حسب المنطقة؟»** لإظهار
   أن النظام يحدد البيانات الناقصة بدل اختراع جواب.
6. اسأل: **«ما أحدث إحصاءات التخزين والخدمات اللوجستية المتاحة حاليًا؟»** لإظهار البحث الرسمي وتاريخ الوصول.

### 5. الخلاصة — 45 ثانية

«الخط المستقيم في المشروع هو: مشكلة تشتت البيانات والتحيز للحجم، ثم Master
Dataset موثق وتطبيع سكاني، ثم أدوات حسابية حتمية، ثم Agent وRAG للوصول الطبيعي
إلى الأدلة، وأخيرًا واجهة تعرض الرقم ومصدره وقيده معًا.»

## أسئلة بديلة للتجربة

- «اعطني ملفًا لوجستيًا لمنطقة القصيم.»
- «اعرض اتجاه طلبات التوصيل ربع السنوي في الرياض ومكة.»
- «ما سياق الموانئ المرتبطة بمنطقة مكة؟»
- «أريد Screening يوازن بين كثافة الطلب ومساحة المستودعات للفرد بالتساوي.»
- «غير الأولوية إلى الطلب 70% والمستودعات 30%.»

## إذا تعطلت الشبكة أو Groq

1. شغّل التطبيق دون المفتاح ليدخل تلقائيًا في **الوضع المحلي المحدود**.
2. استخدم أسئلة المقارنة والملف الإقليمي والاتجاه والموانئ والبيانات المفقودة.
3. وضح أن هذا المسار يشغّل الأدوات والرسوم محليًا، بينما جودة فهم اللغة الكاملة
   تظهر في وضع Groq.
4. استخدم التطبيق المحلي للعرض؛ لا تعتمد على لقطات أو نتائج تاريخية ثابتة.

## إجابات قصيرة لأسئلة اللجنة المتوقعة

**لماذا RAG؟** لأن التعريفات والمنهجيات واللوائح نصوص غير مناسبة للجداول،
ونحتاج استرجاع المقطع والصفحة والمصدر بدل الاعتماد على ذاكرة النموذج.

**لماذا Agent Tools؟** لأن سؤال المستخدم يحدد أي عملية مطلوبة؛ الأداة تنفذ
الحساب الموثوق، والـAgent يختارها ويربط نتائجها بالمحادثة.

**لماذا لا يوجد Gap Score ثابت؟** لأن جودة المؤشرات لا تبرر اختزالها في حقيقة
واحدة؛ المستودعات تراخيص لا سعة، وبعض المؤشرات سياقية أو مترابطة بقوة.

**هل ترتيب Screening توصية؟** لا. هو موضع نسبي تحت معايير وأوزان صريحة، مع
اختبار حساسية، ويحتاج بيانات تكلفة وإشغال وخدمة قبل قرار حقيقي.

**ما فائدة Groq؟** تشغيل سريع ضمن حدود مجانية مناسبة للنموذج الأولي، مع
GPT-OSS 120B للأسئلة التحليلية وLlama 3.1 8B للأسئلة البسيطة والاحتياط.

**كيف منعتم هلوسة الأرقام؟** لا يملك النموذج أداة Python عامة، وكل رقم في
الإجابة يقارن بالأرقام التي أعادتها الأدوات أو بمقتطف RAG؛ المخالفة تحذف أو تحجب.

**لماذا Adaptive Multi-Agent وليس Swarm دائم؟** لأن السؤال البسيط لا يحتاج إلا مكالمة واحدة. Data Agent وResearch Agent يعملان فقط عند الحاجة، وبالتوازي في السؤال المركب، ثم يتحقق النظام من النتيجة قبل العرض؛ وهذا يرفع الدقة دون مضاعفة التكلفة لكل سؤال.
